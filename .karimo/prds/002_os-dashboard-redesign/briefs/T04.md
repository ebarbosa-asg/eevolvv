### app/os/feed/page.tsx

**What it does:** Display diagnostic submissions table with stats, expandable rows showing report text, PostHog funnel metrics bar.

**Data:** Submissions are NOT fetched from an API route — they come from Supabase directly. This page is a **server component** that fetches submissions from Supabase, similar to how the current `app/os/page.tsx` works today.

The expanded row content (the `report` field) renders as a `<TerminalBlock>`.

**Important:** The feed page needs auth guard:
```tsx
const session = await auth(); if (!session) redirect('/signin?callbackUrl=/os/feed')
```

**Data fetch pattern:**
```tsx
// Server component
import { supabase } from '@/lib/supabase'

let submissions: Submission[] = []
if (supabase) {
  const { data } = await supabase
    .from('submissions')
    .select('id, name, email, business_name, business_type, tier, status, email_sent, created_at, report')
    .order('created_at', { ascending: false })
    .limit(20)
  submissions = (data as Submission[]) ?? []
}
```

Since this page needs interactive state (expanding rows, fetching metrics), the server component should pass submissions as a prop to a `'use client'` component `FeedClient`. This is the same pattern the current page.tsx → HubClient pattern uses.

The `Submission` type is defined in `app/os/page.tsx` (kept by T03). Import it from there or redefine locally.

**Stats at top:**
```tsx
const total = submissions.length
const completed = submissions.filter(s => s.status === 'completed').length
const emailsSent = submissions.filter(s => s.email_sent).length
const errors = submissions.filter(s => s.status === 'error').length
```
Render as 4 `<KPIStat>` inside `<Card>`.

**PostHog funnel metrics:** Fetch from `GET /api/os/metrics` in the client component (not a new API route — this exists already, referenced in HubClient.tsx line 272). The funnel metrics bar stays inline. The PostHog link `https://us.posthog.com/project/407291/dashboard/1537727` is hardcoded (HubClient.tsx line 614).

**Expandable rows → TerminalBlock:**
When `expanded === s.id && s.report`, render:
```tsx
<TerminalBlock lines={[{ type: 'primary', value: s.report }]} />
```
Note: the report is pre-wrap text. If `TerminalBlock` doesn't handle multi-line values well, wrap in a `<pre>` inside a `<CardContent>` instead.

**ds/ components:**
- `<SectionMarker num="01" label="DIAGNOSTIC FEED" />`
- `<Card>` for stats row and table
- `<KPIStat>` for 4 stats
- `<Badge>` for submission status
- `<TerminalBlock>` for expanded report
- `<OSTopbar title="FEED" />`
