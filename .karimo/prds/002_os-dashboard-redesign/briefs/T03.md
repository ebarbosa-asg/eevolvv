## Requirements

### Page structure

The new `app/os/page.tsx` is a **server component** (no `'use client'`). It:

1. Runs auth guard: `const session = await auth(); if (!session) redirect('/signin?callbackUrl=/os')`
2. Fetches data in parallel using `Promise.all`
3. Renders `<OSTopbar title="OVERVIEW" />`
4. Renders `<SectionMarker num="00" label="OVERVIEW" />`
5. Renders 4 KPI cards in a 2×2 grid (desktop) / single column (mobile)

### Data fetching

All fetches must use absolute URLs with Next.js `headers()` to forward auth cookies, OR use the API route handlers directly (import and call them). The simplest approach for a server component is to call the underlying data layer directly — but for consistency, fetch from the API routes using the internal URL pattern:

```tsx
const baseUrl = process.env.NEXT_PUBLIC_APP_URL ?? 'http://localhost:3000'

const [tasks, financeData, clients, pipeline] = await Promise.all([
  fetch(`${baseUrl}/api/os/company-tasks`, { headers: { cookie: cookieHeader } }).then(r => r.json()),
  fetch(`${baseUrl}/api/os/finance`, { headers: { cookie: cookieHeader } }).then(r => r.json()),
  fetch(`${baseUrl}/api/os/clients`, { headers: { cookie: cookieHeader } }).then(r => r.json()),
  fetch(`${baseUrl}/api/os/pipeline`, { headers: { cookie: cookieHeader } }).then(r => r.json()),
])
```

Get `cookieHeader` via Next.js `cookies()` from `next/headers`.

Handle fetch errors gracefully — wrap in try/catch, fall back to default values on failure.

### KPI cards

| KPI | Value derivation | Label |
|-----|-----------------|-------|
| Open tasks | `tasks.filter(t => t.status !== 'done').length` | OPEN TASKS |
| MRR | `financeData.mrr ?? '—'` | MRR |
| Active clients | `clients.length` | ACTIVE CLIENTS |
| Pipeline value | `'$' + pipeline.filter(d => d.stage !== 'lost').reduce((s,d) => s+(d.value??0), 0).toLocaleString()` | PIPELINE |
