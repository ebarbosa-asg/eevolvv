## Gotchas

- The `form` state object in `OnboardingForm.tsx` already has `softwareUsername` and `softwarePassword` from IVW-008 (fitness). Dental reuses the same fields — do NOT add duplicate state entries. Only add the dental-unique fields: `practiceManagementSoftware`, `recallRate`, `noShowRate`, `frontDeskCount`, `hipaaAcknowledgment`.
- The HIPAA checkbox state is a string `'true'`/`'false'` (not a boolean) because the `form` state type uses `Record<string, string>` pattern for simplicity with the `set()` helper. The `checked` prop converts it: `checked={form.hipaaAcknowledgment === 'true'}`. The `required` attribute on a checkbox means it must be checked — HTML5 validates this natively.
- `DentalKPIPanels` and `FitnessKPIPanels` are both server components. They can share the same props type shape — consider extracting a shared `SubmissionPanelProps` type if both components are very similar, or just duplicate for now.
- The `isDental` variable must be defined at the top of `OnboardingForm` alongside `isFitness` — both are computed from `industry` prop. Only one branch will render at a time (a client won't be both fitness and dental).
- When the dental admin notification reuses `AdminOnboardingAlert.tsx`, add optional dental props (recall rate, no-show rate, front-desk count, hipaaAcknowledged) alongside the existing fitness props. The send site passes the appropriate subset. Alternatively, create a separate dental template to keep concerns clean.
- "Days in AR" benchmarks for the dental panels show `target: 30 days` as the goal (lower is better). The panel should display: "TARGET: <30 days" and use accent coloring to indicate the gap from target.
