# Brief: IVW-002 — Create lib/industries/fitness.ts config module

## Context

The fitness vertical needs a single source of truth for its intake questions, benchmarks, automation catalog, and vocabulary — all downstream tasks (chat intake, diagnostic prompt, report panels, emails, onboarding) import from this module. This is a pure new-file task: no existing files are modified.

## Codebase Reality

- `lib/` directory contains: `diagnosticPrompts.ts`, `rateLimit.ts`, `supabase.ts`, `format-report.ts`, `posthog-server.ts`. No `industries/` subdirectory exists yet.
- `lib/diagnosticPrompts.ts` already has a `'Gym / Fitness / Wellness'` entry — that entry stays in place and is NOT replaced. The new `'Fitness / Gym / Studio'` key is what the fitness landing page will use going forward. These are separate keys; the old gym entry is legacy.
- No barrel export or index file exists in `lib/industries/` — this task creates both `fitness.ts` and `index.ts`.
- TypeScript path alias `@/lib/` is configured in `tsconfig.json` and maps to `lib/`. All downstream imports will use `@/lib/industries/`.

## What to Build

Create two files.

### File 1: `lib/industries/fitness.ts`

Export a single named constant `VERTICAL_CONFIG` typed as the shape described below. All string literals must match exactly what downstream code will compare against (especially `key` — the chat route and report page will do `=== fitnessConfig.key`).

## Gotchas

- The `key` value `'Fitness / Gym / Studio'` is intentionally different from the existing `'Gym / Fitness / Wellness'` key in `diagnosticPrompts.ts`. Do not confuse them. The old key stays for backward compatibility on existing submissions; the new key is what the fitness landing page will use.
- Use `as const` on the `VERTICAL_CONFIG` object so TypeScript infers literal types. This matters for downstream code that does `=== fitnessConfig.key` type narrowing.
- The `retentionOpportunityFormula` function cannot be `as const` if it's a function property inside an `as const` object — TypeScript handles this fine but be aware the function type won't be narrowed to a literal.
- Do not create a TypeScript interface/type for `VERTICAL_CONFIG` shape yet — the dental config (IVW-009) will need to share the same shape, at which point a shared interface can be extracted. For now, just the implementation.
- The `onboardingFields` array's `type: 'password'` is used by the onboarding form component (IVW-008) to render a password input. The `secure` flag is metadata for the admin notification email.
