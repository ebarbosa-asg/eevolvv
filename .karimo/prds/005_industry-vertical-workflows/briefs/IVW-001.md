# Brief: IVW-001 — Fix dental defaultIndustry key

## Context

The dental landing page passes the wrong industry key to the chat engine, causing dental visitors to receive a generic medical/healthcare diagnostic instead of a dental-specific one. This is a hotfix that ships standalone — no dependencies, no coordination required.

## Codebase Reality

**Bug location:** `app/dental/page.tsx` line 378:
```tsx
<ChatEngine defaultTier="core" defaultIndustry="Medical / Healthcare" />
```

The string `"Medical / Healthcare"` is a valid key in `INDUSTRY_CONTEXT` (lib/diagnosticPrompts.ts line 81) — it matches the medical/healthcare entry which references Athenahealth, Kareo, SimplePractice, RVU, CPT codes. Not relevant to dental.

The string `"Dental / Oral Health"` does NOT exist anywhere in `INDUSTRY_CONTEXT`. The `buildSystemPrompt` function at line 240 of `lib/diagnosticPrompts.ts` falls back to `DEFAULT_CONTEXT` when the key is missing:
```ts
export function buildSystemPrompt(industry: string): string {
  const context = INDUSTRY_CONTEXT[industry] ?? DEFAULT_CONTEXT
  return `${BASE_PROMPT}\n\n${context}`
}
```

So dental visitors currently get either a generic business report OR a medical/healthcare report — depending on how far the key mismatch propagates.

**`INDUSTRY_CONTEXT` structure** (lib/diagnosticPrompts.ts line 48): a `Record<string, string>` where each value is a multi-line string starting with `INDUSTRY CONTEXT — {NAME}:` and containing: Key automation targets, Industry benchmarks, Common stack, Highest-ROI automations, Language.

**Existing entry to study as a pattern** — `'Gym / Fitness / Wellness'` at line 57 is the cleanest example entry to follow for structure.

**`getIndustryShortName`** map at line 246 does NOT include `'Dental / Oral Health'` — add it (`'Dental / Oral Health': 'Dental'`).

## What to Build

**Change 1 — `app/dental/page.tsx` line 378:**
Change `defaultIndustry="Medical / Healthcare"` to `defaultIndustry="Dental / Oral Health"`.

**Change 2 — `lib/diagnosticPrompts.ts`:**
Add a new entry to the `INDUSTRY_CONTEXT` object keyed exactly as `'Dental / Oral Health'`. Insert it near the `'Medical / Healthcare'` entry (around line 81) to keep related verticals grouped.

The entry must contain:
- **Key automation targets:** recall campaign outreach, no-show confirmation + rescheduling, insurance pre-authorization follow-up, new patient intake forms, treatment plan follow-up, AR aging follow-up, patient reactivation (lapsed 12+ months)
- **Industry benchmarks:**
  - Recall rate: industry avg 55-65%, top practices 85-90%; every 10% gain in recall rate = ~$50K–$100K/yr per provider
  - No-show rate: avg 4-7%, top practices <1%; each missed slot = $200-$300 in lost production
  - Treatment acceptance: avg 55-65%, top practices 70-80%
  - Collection rate: target 98%+
  - Days in AR: target <30 days
- **Common stack:** Dentrix, Eaglesoft, Open Dental, Curve Dental, Weave, NexHealth, Lighthouse 360, RevenueWell, Carestream
- **Highest-ROI automations:** recall outreach sequence, no-show confirmation workflow, pre-authorization tracking, new patient nurture sequence, AR follow-up automation
- **Language:** use dental terms: "recall rate," "hygiene appointment," "treatment acceptance," "days in AR," "production," "collection rate," "perio," "new patient," "recare," "unscheduled treatment," "insurance aging"

**Change 3 — `lib/diagnosticPrompts.ts` `getIndustryShortName` map:**
Add `'Dental / Oral Health': 'Dental'` to the map.
