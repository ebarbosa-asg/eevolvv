# Brief: IVW-006 — Industry-aware report page — fitness KPI panels

## Context

The report page currently renders generic markdown regardless of what industry the user is in. Fitness gym owners who complete a diagnostic should see visual KPI panels comparing their specific metrics (churn rate, lead conversion, ARPM) against industry benchmarks with dollar-value opportunity calculations — above the main report text. This task adds the `industry` field to the Supabase query and conditionally renders a `FitnessKPIPanels` component.

## Codebase Reality

**File to modify:** `app/report/[id]/page.tsx` (129 lines)

**Current Supabase query** (lines 25-29):
```ts
const { data: submission, error } = await supabase
  .from('submissions')
  .select('id, business_name, report, tier, email, created_at')
  .eq('id', id)
  .eq('status', 'completed')
  .maybeSingle()
```
`industry` is NOT in the select. It must be added.

**`submissions` table** has `industry TEXT` column (migration 001 line 15). No schema change needed — just add to the select.

**Current report render** (lines 81-86):
```tsx
<div className="site-rail mx-auto">
  <div
    className="report-content"
    style={{ padding: '40px 32px' }}
    dangerouslySetInnerHTML={{ __html: reportHtml }}
  />
```
The KPI panels should be inserted before this `report-content` div, inside the `site-rail` container.

**Design system:** `components/ds/` exists and is fully populated. Confirmed components: `KPIStat.tsx`, `DataRow.tsx`, `Card.tsx`, `CardHeader.tsx`, `CardContent.tsx`, `Badge.tsx`, `Button.tsx`, `Input.tsx`, `Label.tsx`, `SectionMarker.tsx`, `Sidebar.tsx`, `StatusPill.tsx`, `TerminalBlock.tsx`, `Textarea.tsx`. Use these components — do NOT use inline styles or raw Tailwind class blocks. See `components/ds/README.md` for usage reference.

**`fitnessConfig.kpiPanels`** (from IVW-002): 5 panel definitions — churn, leadConversion, arpm, annualRetention, classUtilization.

**`SubmissionRow` type:** The existing page doesn't define a named type for the Supabase row. Define one locally in the new component file.

**`report` and `submission_data` access:** The report page passes `submission.report` to `formatReport()`. The KPI panels need access to the raw submission data. The submission row from Supabase will include the `report` TEXT field — but the actual KPI values (churn rate, member count, ARPM) are embedded in the conversation extracted data, not in separate columns. They are part of the `report` text or the underlying intake data. Since the submissions table does not have separate numeric KPI columns, the panels will need to render "not captured" for values not directly stored as columns, while still showing the industry benchmarks for comparison.

## Gotchas

- The `submissions.industry` column already exists (migration 001 line 15). This is not a blocking dependency on IVW-003 — that migration is for the `clients` table.
- The report page is a React Server Component (no `'use client'` directive). `FitnessKPIPanels` should also be a server component (no hooks needed) to avoid unnecessary hydration.
- Use `components/ds/` components for all UI — `KPIStat`, `DataRow`, `Card`, `Badge` are confirmed to exist. Do NOT use inline styles as a fallback and do NOT build UI from raw Tailwind classes. This is a hard rule per CLAUDE.md: "Always use components/ds/ — never build UI from raw Tailwind classes."
- The submission's raw intake KPI values (actual churn rate, member count) are embedded in the `report` TEXT field as narrative prose, not extractable columns. The KPI panels should honestly state the benchmarks and instruct the user to "review your report" for their specific numbers — or attempt a regex extraction from `submission.report` if the fitness INDUSTRY_CONTEXT (IVW-005) causes Claude to output structured data for those metrics. Do not fabricate values.
- `dangerouslySetInnerHTML` is used for the report body — the KPI panels render as normal React JSX above it. Keep these separate.
