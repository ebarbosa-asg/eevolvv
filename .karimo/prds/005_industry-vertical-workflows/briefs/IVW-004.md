# Brief: IVW-004 — Inject fitness-specific intake questions into api/chat/route.ts

## Context

The chat engine asks the same 7 generic questions to every visitor regardless of industry. Fitness gym owners are never asked about churn rate, EFT failures, or lead conversion — so Claude cannot give expert fitness recommendations. This task injects the fitness-specific question set into the system prompt when the fitness landing page is the source.

## Codebase Reality

**File to modify:** `app/api/chat/route.ts` (73 lines total)

**Current system prompt construction** (lines 6-32):
```ts
const CHAT_SYSTEM_PROMPT = `You are eevolvv's AI business diagnostic assistant...
RULES:
- Start by asking what kind of business they run and what their name is
- Once you have collected business type + at least 2 pain points + email, end your message with exactly: [READY]
...`

export async function POST(req: NextRequest) {
  const { messages, defaultIndustry } = body
  const systemPrompt = defaultIndustry
    ? `${CHAT_SYSTEM_PROMPT}\n\nINDUSTRY OVERRIDE: This user came from the ${defaultIndustry} landing page. Their industry is already confirmed: "${defaultIndustry}". Do NOT ask what kind of business they run — skip that question entirely. Ask their name and business name first, then go straight into their specific pain points, team size, revenue range, current tools, and email.`
    : CHAT_SYSTEM_PROMPT
```

The INDUSTRY OVERRIDE block (lines 30-31) already handles the "skip what kind of business" behavior. This task replaces the generic "specific pain points, team size, revenue range, current tools" guidance with the fitness-specific question list when the industry matches.

**Import path:** `@/lib/industries` will resolve to `lib/industries/index.ts` which exports `fitnessConfig` (created in IVW-002).

**Request body shape** (line 22): `{ messages: { role: 'user' | 'assistant'; content: string }[]; defaultIndustry?: string }` — `defaultIndustry` is already being received, no schema change needed.

**Key constraint:** The `[READY]` signal behavior, streaming infrastructure, Anthropic client call, and all other routes must remain exactly unchanged.

   ```ts
   function buildSystemPrompt(defaultIndustry?: string): string {
     if (!defaultIndustry) return CHAT_SYSTEM_PROMPT

     if (defaultIndustry === fitnessConfig.key) {
       const questionList = fitnessConfig.intakeQuestions
         .map((q, i) => `${i + 1}. ${q}`)
         .join('\n')
       return `${CHAT_SYSTEM_PROMPT}\n\nINDUSTRY OVERRIDE: This user came from the Fitness / Gym / Studio landing page. Their industry is already confirmed: "${fitnessConfig.key}". Do NOT ask what kind of business they run — skip that question entirely.\n\nAsk their name and business name first, then work through these fitness-specific questions (one or two at a time, in a natural conversational order):\n\n${questionList}\n\nOnce you have their name, business name, answers to at least 4 of these questions, and their email address, end your message with exactly: [READY] on its own line.`
     }

     // Generic industry override (non-fitness)
     return `${CHAT_SYSTEM_PROMPT}\n\nINDUSTRY OVERRIDE: This user came from the ${defaultIndustry} landing page. Their industry is already confirmed: "${defaultIndustry}". Do NOT ask what kind of business they run — skip that question entirely. Ask their name and business name first, then go straight into their specific pain points, team size, revenue range, current tools, and email.`
   }
   ```

## Gotchas

- The comparison `defaultIndustry === fitnessConfig.key` will only match if `fitnessConfig.key` is exactly `'Fitness / Gym / Studio'`. Confirm that IVW-002 set this value correctly before writing the conditional.
- The `CHAT_SYSTEM_PROMPT` constant at line 6 instructs Claude to end with `[READY]`. The fitness override path should preserve this signal — either by referencing `CHAT_SYSTEM_PROMPT` as the base (which it does) or by explicitly restating it. Do not lose the `[READY]` instruction.
- `max_tokens: 400` on the Anthropic call (line 44) limits response length. The fitness questions are detailed — Claude may need to ask them across multiple turns rather than one message. This is correct behavior; no token limit change is needed.
- Do not create a separate API route for fitness. The same `/api/chat` route handles all verticals.
- The `buildSystemPrompt` local function name shadows nothing — the imported `buildSystemPrompt` from `@/lib/diagnosticPrompts` is not imported in this file (that's only in `api/diagnostic/route.ts`).
