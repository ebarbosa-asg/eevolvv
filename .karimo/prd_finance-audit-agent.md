# KARIMO PRD: Finance Audit Agent (Day 1)

## Overview

**Project:** Finance Audit Agent  
**Goal:** Build foundational agent infrastructure for autonomous financial auditing on eevolvv  
**Scope:** Day 1 = BaseAgent class, shared types, Supabase schema migrations, RAG ingest/retrieval, upload API  
**Owner:** KARIMO  
**Created:** 2026-05-03  
**Context:** eevolvv.com — Next.js, TypeScript, Tailwind, Supabase, @anthropic-ai/sdk claude-sonnet-4-6

**Why:** Finance audit is a high-contract-value enterprise wedge (22.8% CAGR market, QA/compliance-driven). This Day 1 build lays the pipes: agent framework, document ingestion, RAG retrieval, and tracing. Finance Audit Agent will follow a 4-phase pipeline: Diagnose → Onboard → Build Task Agents → Maintain.

---

## Tech Constraints & Decisions

### Stack
- **Framework:** Next.js 14.2.5, App Router, TypeScript 5
- **AI:** Anthropic SDK (`@anthropic-ai/sdk` ^0.91.1), `claude-sonnet-4-6`
- **Database:** Supabase with pgvector for embeddings
- **Embeddings:** Ollama `nomic-embed-text` (local, POST http://localhost:11434/api/embeddings)
- **Structured Output:** Zod 3.23.8
- **Observability:** Langfuse 3.31.0 (gracefully optional, trace-all-runs pattern)
- **Document Parsing:** pdf-parse 2.4.5, xlsx (SheetJS, already installed), papaparse (CSV)
- **Rate Limiting:** IP-based, stored in Supabase `rate_limits` table (create in migration)
- **Auth:** Basic: x-api-key header against INTERNAL_API_KEY env var

### Environment Variables (add to .env.local + Vercel dashboard)


### Constraints
- **Retry Logic:** Exponential backoff, max 3 attempts, never exceed API rate limits
- **Langfuse:** Graceful degradation — if LANGFUSE_SECRET_KEY missing, tracing is a no-op, never blocks agent runs
- **Chunking:** 500 tokens max per chunk, 50 token overlap, preserve row/context for financial data
- **Vector DB:** pgvector with ivfflat index on `document_chunks.embedding`
- **RLS Policies:** Service role full access, restrict anon queries via clientId isolation
- **API Key Auth:** All agent upload/run endpoints require x-api-key header matching INTERNAL_API_KEY

#### Task 1.2: Supabase Migration – Agent Infrastructure Schema
**File:** `/supabase/migrations/[timestamp]_agent_infra.sql`

**Description:**  
Create Supabase schema for documents, chunks, agent runs, findings, and rate limiting. Timestamp auto-generated by migration system.

**Acceptance Criteria:**
- [x] Create `documents` table:
  ```sql
  CREATE TABLE documents (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    client_id text NOT NULL,
    filename text NOT NULL,
    file_type text NOT NULL, -- 'csv', 'pdf', 'xlsx'
    content text,            -- raw text after parsing
    created_at timestamp DEFAULT now()
  );
  CREATE INDEX idx_documents_client_id ON documents(client_id);
  ```
- [x] Create `document_chunks` table:
  ```sql
  CREATE TABLE document_chunks (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id uuid NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    content text NOT NULL,
    embedding vector(768),
    chunk_index int NOT NULL,
    metadata jsonb DEFAULT '{}',
    created_at timestamp DEFAULT now()
  );
  CREATE INDEX idx_document_chunks_document_id ON document_chunks(document_id);
  CREATE INDEX idx_document_chunks_embedding ON document_chunks USING ivfflat(embedding vector_cosine_ops);
  ```
- [x] Create `agent_runs` table:
  ```sql
  CREATE TABLE agent_runs (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    client_id text NOT NULL,
    agent_type text NOT NULL, -- 'finance-audit', 'qa-compliance', etc.
    input jsonb NOT NULL,
    output jsonb,
    langfuse_trace_id text,
    status text DEFAULT 'pending', -- 'pending', 'running', 'completed', 'error'
    error text,
    created_at timestamp DEFAULT now(),
    updated_at timestamp DEFAULT now()
  );
  CREATE INDEX idx_agent_runs_client_id ON agent_runs(client_id);
  CREATE INDEX idx_agent_runs_status ON agent_runs(status);
  ```
- [x] Create `findings` table:
  ```sql
  CREATE TABLE findings (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    agent_run_id uuid NOT NULL REFERENCES agent_runs(id) ON DELETE CASCADE,
    severity text NOT NULL, -- 'HIGH', 'MED', 'LOW'
    category text NOT NULL,
    description text NOT NULL,
    evidence jsonb DEFAULT '{}',
    recommendation text,
    created_at timestamp DEFAULT now()
  );
  CREATE INDEX idx_findings_agent_run_id ON findings(agent_run_id);
  CREATE INDEX idx_findings_severity ON findings(severity);
  ```
- [x] Create `rate_limits` table:
  ```sql
  CREATE TABLE rate_limits (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    client_id text NOT NULL,
    request_count int DEFAULT 0,
    window_start timestamp DEFAULT now(),
    created_at timestamp DEFAULT now()
  );
  CREATE INDEX idx_rate_limits_client_id ON rate_limits(client_id);
  ```
- [x] Enable pgvector extension: `CREATE EXTENSION IF NOT EXISTS vector;`
- [x] Set up RLS policies:
  - Service role: full access to all tables
  - Anon: NO access (queries must use service role)
  - Add policy comments explaining security model
- [x] Create SQL function `match_document_chunks`:
  ```sql
  CREATE OR REPLACE FUNCTION match_document_chunks(
    query_embedding vector(768),
    client_id_filter text,
    match_count int DEFAULT 5
  ) RETURNS TABLE(
    id uuid,
    content text,
    similarity float,
    metadata jsonb
  ) AS $$
  BEGIN
    RETURN QUERY
    SELECT
      dc.id,
      dc.content,
      (1 - (dc.embedding <=> query_embedding)) AS similarity,
      dc.metadata
    FROM document_chunks dc
    JOIN documents d ON dc.document_id = d.id
    WHERE d.client_id = client_id_filter
    ORDER BY dc.embedding <=> query_embedding
    LIMIT match_count;
  END;
  $$ LANGUAGE plpgsql;
  ```
- [x] Schema validation: All tables have proper indexes, FKs, and defaults

**Tech Notes:**
- Use pgvector's `<=>` (cosine distance) operator for similarity search
- IVF-flat index critical for performance on large chunk sets
- RLS strictly enforces client_id isolation — no cross-client data leakage
- Rate limits table follows IP-based pattern from existing diagnostic API

### WAVE 3: RAG Pipeline (Ingest + Retrieval)

#### Task 3.1: RAG Ingest Pipeline
**File:** `/lib/rag/ingest.ts`

**Description:**  
Async function to parse documents (CSV, PDF, XLSX), chunk with token-aware overlap, embed via Ollama, and store in Supabase.

**Acceptance Criteria:**
- [x] Export async function `ingestDocument(file: File, clientId: string): Promise<{ documentId: string, chunkCount: number, success: boolean }>`
- [x] File type detection via `file.type` or `file.name`:
  - `.csv` → parse with papaparse or manually split by newlines
  - `.pdf` → use pdf-parse library
  - `.xlsx` → use xlsx (SheetJS) package
- [x] Parsing logic:
  - CSV: preserve row structure in metadata (rowIndex, headers)
  - PDF: extract text preserving section structure where possible
  - XLSX: extract all sheets, tag with sheet name in metadata
- [x] Chunking strategy:
  - Target: 500 tokens max per chunk (estimate: ~1 token per 4 chars)
  - Overlap: 50 tokens between chunks
  - Preserve row context for CSV/XLSX (don't split a row)
  - Preserve paragraph structure for PDF
- [x] Embedding logic:
  - Create embedding for each chunk via POST `${OLLAMA_ENDPOINT}/api/embeddings`
  - Model: `"nomic-embed-text"`
  - Request body: `{ "model": "nomic-embed-text", "prompt": chunkText }`
  - Response: `{ embedding: number[] }` (768-dim vector)
  - Gracefully handle Ollama unavailable (warn, continue without embedding)
- [x] Supabase insertion:
  - Create document record (id, client_id, filename, file_type, content)
  - For each chunk: insert into document_chunks (document_id, content, embedding, chunk_index, metadata)
  - Use `upsert` pattern if re-ingesting same file
- [x] Return: `{ documentId: uuid, chunkCount: number, success: boolean }`
- [x] Error handling:
  - Log all errors; don't throw (resilient pattern)
  - Return success: false if any chunk fails
  - Partial success OK (e.g., 8/10 chunks embedded, 10/10 stored)

**Tech Notes:**
- papaparse: `npm install papaparse` (not in package.json yet, KARIMO will add)
- pdf-parse: already installed
- xlsx: already installed (SheetJS)
- Token estimate: ~4 chars per token (rough; fine for chunking purposes)
- Ollama endpoint: check `process.env.OLLAMA_ENDPOINT` (default `http://localhost:11434`)
- Test file size: support up to 50MB (adjust if Ollama times out)

### WAVE 4: Document Upload API

#### Task 4.1: Document Upload API Route
**File:** `/app/api/documents/upload/route.ts`

**Description:**  
POST endpoint to accept multipart/form-data with file and clientId, validate auth, call ingestDocument, and return metadata.

**Acceptance Criteria:**
- [x] Method: POST
- [x] Content-Type: multipart/form-data
- [x] Request params:
  - `file` (FormData.file) — the document file
  - `clientId` (FormData.text) — identifier for client (text string, not uuid)
- [x] Auth validation:
  - Require header `x-api-key` matching `process.env.INTERNAL_API_KEY`
  - Return 401 if missing or mismatch
  - Specific error message: "Invalid or missing API key."
- [x] Validation:
  - Check file size ≤ 50MB (return 413 if exceeds)
  - Check file type in whitelist: ['text/csv', 'application/pdf', 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet']
  - Check clientId not empty and ≤ 255 chars
  - Return 400 with field-specific error if validation fails
- [x] Call ingestDocument:
  - Pass `file` and `clientId`
  - Await response
- [x] Response on success (200):
  ```json
  {
    "success": true,
    "documentId": "uuid-string",
    "chunkCount": 42,
    "filename": "original-filename.csv"
  }
  ```
- [x] Response on partial success (202):
  ```json
  {
    "success": false,
    "documentId": "uuid-string",
    "chunkCount": 42,
    "warning": "Failed to embed 2 chunks; stored anyway."
  }
  ```
- [x] Response on failure (500):
  ```json
  {
    "error": "Failed to ingest document",
    "details": "..."
  }
  ```
- [x] Rate limiting (optional, can skip for Day 1):
  - Check `client_id` against `rate_limits` table
  - Limit to 50 documents per client per day
  - Return 429 if exceeded
- [x] Logging:
  - Log success/failure with documentId, chunkCount, filesize
  - Use PostHog or console.error for errors

**Tech Notes:**
- Use `NextRequest` and `NextResponse` from next/server
- Use `req.formData()` to parse multipart (built-in, no extra deps)
- File is `FormData.File` with `.text()`, `.stream()`, or `.arrayBuffer()` methods
- API Key should be random string set in .env.local (e.g., `INTERNAL_API_KEY="sk_test_1234abcd"`)
- For now, simple string comparison auth; no JWT/OAuth
